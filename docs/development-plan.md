# 开发计划

## 工作方式

M0 在 `main` 建立初始化提交。M1–M7 每阶段使用独立 `feat/...` 分支、聚焦 Commit 和 Pull Request；PR 未经人工确认不合并。每阶段结束运行测试并记录完成内容、修改文件、结果、遗留问题和下一步。

## M0：项目底座和 Docker（本阶段）

- 完成产品、架构、数据库、API、Agent 和验收设计。
- 建立 React + TypeScript + Vite 前端。
- 建立 FastAPI + SQLAlchemy + SQLite 后端和健康检查。
- 添加 `.env.example`、安全 `.gitignore`、Dockerfiles 和 Compose。
- 添加后端单元测试、前端最小测试/构建检查。
- 验证本地与容器启动，创建初始化提交并推送 `main`。

## M1：管理员、部门、员工和项目

- 实现组织和项目数据模型、迁移、CRUD 与成员分配。
- 实现演示角色切换与项目可见性校验。
- 完成总工作台、管理员和部门项目列表页面。

## M2：聊天与上下文持久化

- 实现会话创建、重命名、历史和消息持久化。
- 实现项目摘要、结构化范围和上下文构建器。
- 支持消息附件引用，建立 ChatGPT 风格项目页面。

## M3：销售报表导入

- 实现 10 MB CSV/XLSX 上传、SHA-256 去重和安全存储。
- 实现字段映射、验证、预览、确认事务、报告和错误导出。
- 生成固定种子的 18 个月仿真数据与坏行样例。

## M4：DeepSeek 与受控工具

- 实现 DeepSeek/Mock 文本 Provider。
- 实现 Tool 注册表、六个 Pydantic Tool 契约与调用追踪。
- 实现销售/库存受控查询和 Agent Run 可观测性。

## M5：选品分析与补货 Skill

- 实现统一指标服务、趋势、库存压力和确定性补货规则。
- 实现选品 Workflow、追问继承和人工确认提示。
- 让 Dashboard 与 Agent 复用同一计算服务。

## M6：千问商品图编辑

- 实现安全图片上传、不可变版本链和下载。
- 先交付 Mock 图片 Provider，再接真实千问适配器。
- 实现失败重试、消息图片引用和生成状态 UI。

## M7：测试、追踪与演示完善

- 补全单元、集成、端到端和回归测试。
- 完善日志、错误处理、运行追踪和演示脚本。
- 校验隐私、安全、文件忽略、部署说明和最终验收场景。

## 依赖关系

- M1 依赖 M0；M2 依赖 M1。
- M3 依赖 M1，可与 M2 后半段并行开发。
- M4 依赖 M2/M3 的数据和消息基础。
- M5 依赖 M3/M4；M6 依赖 M2/M4 的 Provider/追踪模式。
- M7 依赖所有功能里程碑。
