# Agent、Tool、Skill 与 Workflow 设计

## 1. 概念边界

- **Model**：DeepSeek 文本模型或千问图片编辑模型，提供概率性推理/生成。
- **Provider**：供应商 API 适配器，统一超时、重试、错误和 Mock 实现。
- **Tool**：具有 Pydantic 输入输出的受控原子后端函数。
- **Skill**：组合业务规则与领域服务的可测试能力，例如补货决策。
- **Workflow**：多步骤、有状态、可追踪、可重试的业务流程。
- **Agent**：用系统提示词理解意图、选择白名单 Tool 并解释结构化结果。

模型不直接操作数据库、文件系统或执行环境。Tool 不接受 SQL/Python/Shell 字符串，也不把数据库连接传给模型。

## 2. Provider 接口

文本 Provider 接受规范化消息、可用 Tool schema、模型名和超时，返回文本或结构化 Tool 请求。图片 Provider 接受源文件引用、提示词和模型参数，返回生成文件流/任务状态。两者均实现：

- `MockProvider`：固定、可复现、无需 Key。
- 真实 Provider：从环境变量读取配置，不记录 Key。
- 统一错误：认证、限流、超时、上游失败、响应格式错误。

## 3. Tool 注册表

| Tool | 输入重点 | 输出重点 |
| --- | --- | --- |
| `query_sales_metrics` | site/platform/date range/category/SKU/granularity | 销量、收入、成本、毛利、退款及数据范围 |
| `query_inventory_status` | site/platform/as_of/category/SKU | 可售、预留、在途、最近快照 |
| `calculate_sales_trend` | 已验证的时间序列 | 趋势、环比、季节性摘要 |
| `calculate_inventory_pressure` | 销速与库存结构 | 覆盖天数、压力等级、缺货/积压风险 |
| `recommend_restock` | 指标、提前期、安全天数、目标覆盖 | 是否补货、确定性建议数量和规则依据 |
| `get_import_batch_status` | batch_id/project_id | 状态、成功/失败行数、错误摘要 |

每次调用先进行 Pydantic 验证，再通过领域服务执行，并写入 `tool_calls`：工具名、规范化输入、输出摘要、状态、耗时和错误。大数据结果保留在领域存储，日志只保存摘要。

## 4. Skill 设计

### 销售指标 Skill

统一定义销量、收入、毛利、毛利率、退款率和环比公式，供 Dashboard 与 Tool 复用。

### 库存压力 Skill

以可售库存、在途库存、近 N 天日均销量和数据新鲜度计算覆盖天数；通过确定性阈值划分低库存、健康、偏高和积压。

### 补货建议 Skill

建议数量由代码计算，例如：

`max(0, 目标覆盖期需求 + 安全库存 - 可用库存 - 确认可用在途)`

规则同时考虑最小历史长度、销量趋势、提前期、退款异常和数据新鲜度。缺少关键数据时返回“无法建议”而不是猜测。

## 5. Workflow 设计

### 选品分析 Workflow

1. 解析并合并结构化范围。
2. 检查站点、平台、时间和商品是否足够明确。
3. 调用销售查询和库存查询。
4. 调用趋势与库存压力计算。
5. 调用补货规则。
6. 由 DeepSeek 解释范围、指标、建议、风险和依据。
7. 保存消息、范围、Tool 记录和运行状态。

### 报表导入 Workflow

上传、哈希去重、解析、映射、校验、预览、人工确认、事务写入、报告生成。步骤状态可恢复，确认前不写事实表。

### 图片编辑 Workflow

原图登记、请求保存、Provider 执行、结果文件校验、版本落库、消息引用。失败保留上下文，重试不得覆盖源文件或历史版本。

## 6. 上下文策略

每次模型调用按以下顺序组装：部门系统提示词、项目摘要、当前结构化分析范围、最近若干轮消息、当前用户消息、最新工具结果。结构化范围至少保存站点、平台、时间、品类、SKU 和粒度。

追问可以继承实体与范围，但补货等关键决策必须重新通过 Tool 获取最新数据。上下文截断优先保留系统规则、结构化范围和最新 Tool 结果。

## 7. 可观测性与安全

- 每轮生成唯一 `agent_run_id`，每个 Tool 调用关联该运行。
- 记录状态、时延、Provider/模型、输入输出摘要和错误分类。
- Provider 超时与可重试错误使用有限重试；业务校验错误不重试。
- Mock 响应和仿真数据使用固定种子。
- 自然语言结果必须明确“建议需人工确认，MVP 不执行采购”。
